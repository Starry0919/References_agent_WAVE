### 2.2 数据流与状态流

```
CandidateDesign/DesignPortfolio(Problem 4 真实产物)
  → intake.open_evaluation_case（context freeze + claim inventory）  [evaluation_pending → deterministic_validation]
  → deterministic.run_deterministic_checks                          [→ evidence_review]
  → evidence.assess_evidence                                        [→ model_review]
  → model_eval.assess_model_records                                 [→ scientific_review]
  → critic.run_all_reviews（generalist + 条件触发领域 critic）        [→ candidate_comparison]
  → comparator.build_candidate_evaluation_vectors（+ Pareto）        [→ meta_review]
  → revision.generate_revision_tasks + meta_review.synthesize_meta_review
  → scientific_revision_gate → [revision_required | awaiting_human_decision]
  → (revision_required) revision.apply_revision → 新 CandidateDesign 版本 → 重新进入 evaluation_pending
  → (awaiting_human_decision) human_gate.record_human_evaluation_decision → [approved_for_planning|approved_for_build|revise|request_more_evidence|request_model_run|returned_to_diagnosis|rejected|held|stopped]
  → memory.record_memory_event（append-only lesson）
```

### 2.3 与 Problem 1–4 的接口

- **输入（doc05 §8）**：`run_scientific_evaluation(portfolio_id=...)` 直接读取 Problem 4 的 `DesignPortfolio`/`CandidateDesign`/`BuildTestPackage`/`CounterfactualRun`，不接受自由文本。
- **输出**：`RevisionTask`/`CandidateEvaluationVector`/`MetaReviewDecision`/`HumanEvaluationDecision` 均可被 Problem 4 消费；`revision.apply_revision` 直接调用 `portfolio_service.revise_candidate`（Problem 4 现成函数），新候选是 Problem 4 的真实 `CandidateDesign` 行，不是 Problem 5 私有影子对象。
- **Workflow Guard（doc05 §6）**：`gate_hooks.check_before_planning_complete`/`check_before_build_approval` 挂入 `harness/engineering_design/governance_service.py` 的 `mark_planning_complete`/`record_human_decision`，未使用 Problem 5 的项目零行为变化，使用了则强制要求科学 Human Gate 先行通过。
- **返回 Problem 3（doc05 §7）**：`diagnosis_return.create_diagnosis_return_request` 真实调用 `harness.diagnosis.service.start_diagnosis_session`，创建新诊断 session（而非编辑旧 `DiagnosisDecision`）。
- **写入 Problem 2 Memory**：每个 mutating 步骤都调用 `harness.memory.event_store.append_event`，写入与 Problem 1–4 共用的同一张 `ProjectEvent` 表（15 个新 `EVAL_*` 事件类型）。

## 3. Scientific Safeguards

- **证据类型隔离**：`ScientificClaim.source_type`/`EvidenceAssessment.evidence_type` 强制枚举 doc05 §2.2 的 7 类；`claims.py::_claim_source_for_links` 对多来源证据取**最弱**映射，绝不把 curated_knowledge 与 llm_hypothesis 混合后报告为更强的等级。
- **Transferability（可迁移性）**：`EvidenceAssessment` 8 个匹配维度独立保存（非合并总分）；真实解析知识库后发现多数条目自述"非特定验证过的实验结果"，因此 condition/process/time/measurement 维度诚实返回 `unknown`（`test_2_condition_mismatch_produces_transferability_finding` 验证）。
- **Model honesty**：`ModelEvaluationRecord.run_status` 严格六态（`computed`/`not_computed`/`unavailable`/`failed`/`out_of_domain`/`stale`），当前 fixture 因未请求任何模型计算，统一诚实返回 `not_computed`（`test_model_adapter_honesty_states_are_distinct` 验证），从未拿 `0` 或伪造值填充。
- **Uncertainty**：`CandidateEvaluationVector` 每个维度都是 `{mode, value_or_level, ...}`，`mode="not_computed"` 时 `value_or_level` 恒为字符串 `"unknown"`，从不是数值 `0`（`test_not_computed_is_never_converted_to_zero`/`test_unknown_is_not_low_risk` 验证）。
- **Human Gate**：`human_gate.record_human_evaluation_decision` 是唯一写入 `approved_for_planning`/`approved_for_build` 的入口；proposer 不能自批准（复用 `SelfApprovalError`，`test_self_approval_rejected` 验证）；`approve_for_build` 前强制 `DET-007`/`DET-008` 检查（`test_deterministic_critical_finding_blocks_build` 验证）；达到修订轮数上限时进入 `awaiting_human_decision` 而非自动批准（`test_max_rounds_does_not_auto_approve` 验证）。
- **安全/合规硬门**：`safety_ethics_critic` 是本仓库中第一个显式的 biosafety policy hook（审计确认仓库此前无此机制）；essential-gene 命中触发 `severity="critical", blocking=True`，且 `CandidateEvaluationVector.risk` 永不被 `production_potential` 抵消（两者是独立维度，不折算进单一综合分——`decision.py`/`comparator.py` 全程未出现任何加权求和的 `overall_score`）。

| AI-driven Protein Design | `critic.py::_DOMAIN_TRIGGERS` 仅在真实蛋白结构/功能声明存在时触发 protein_design_critic | 本轮 fixture（代谢工程敲除/过表达）未触发该 critic，符合"不相关模块不强制产生伪评价"（doc05 §4.6），已在代码注释与测试中说明 |
| SAMPLE | `CandidateEvaluationVector.uncertainty`/`information_gain` 维度（qualitative，非贝叶斯数值） | `CONFIDENCE_CLASSES` 无 `high` 以上的伪精确概率；`meta_review.py::_worst_confidence` 明确取最弱值，从不用当前无校准数据输出可靠成功率 |

## 7. Honest Degradation

| 场景 | 系统行为 | 用户可见结果 |
|---|---|---|
| 无第二 LLM provider / 无实时 LLM 调用 | `critic.py` 采用确定性 rubric 引擎（与 Problem 1-4 全仓库既定模式一致：无任何 service 层同步调用 `harness.llm`） | `ScientificReview.shared_model_risk=True`，`limitations` 字段写明"deterministic rubric engine - no live LLM/second-provider review has been run" |
| 无真实 GEM/vEcoli 计算被请求 | `ModelEvaluationRecord.run_status="not_computed"` | API/测试均可见诚实 `not_computed`，从不是编造的 `objective_value` |
| 知识库条目缺培养条件元数据 | `EvidenceAssessment.condition_match/process_match/time_match/measurement_match="unknown"` | Reviewer finding 明确指出"condition_match is unknown"而非默认视为匹配 |
| 无前端面板 | 未新建第二套前端（doc05 §10.2 "不得为了展示而搭第二套前端"） | 仅通过 `harness/api/scientific_evaluation.py` 的 15 条路由 + `tests/scientific_evaluation/test_api.py` 验证的 JSON 契约提供数据；`web/index.html` 未改动 |

## 8. Remaining Risks

- **same-model bias**：`shared_model_risk` 恒为 `True`——本轮未接入第二 LLM provider 或独立 Reviewer 模型，`critic.py` 的"独立性"仅体现在 context/rubric/evidence 三层（代码级验证：不读取 Designer 隐藏推理、rubric 专找失败条件、独立解析证据），**不**体现在模型层面。真实多模型/多供应商 Reviewer 是未来增强项，非本轮伪造覆盖。
- **知识库覆盖窄**：`action_database.json` 仅 5 条策略、`ddr_database/` 仅 4 篇 DDR，且均无培养条件元数据——这决定了 `EvidenceAssessment` 的 condition/process/time 维度在当前知识库下几乎总是 `unknown`，这是真实数据缺口的诚实反映，而非评估器的缺陷；扩充知识库元数据字段是后续工作。
- **确定性 critic 的表达力上限**：rubric 是固定规则集，无法像真实 LLM/领域专家那样发现规则未预见的新颖失败模式；`critic.py` 模块 docstring 已记录一个真实 LLM-backed critic adapter 应如何接入现有 schema（`ScientificReview`/`CriticFinding` 结构已就绪），留作后续工作，不在本轮内谎称已实现。
- **CandidateEvaluationVector 部分维度为 qualitative 而非真实数值**：`experimental_cost`/`time_to_result` 依赖 `BuildTestPackage.estimated_time_cost_and_risk`（人工/agent 填写），本轮 fixture 未填写，故诚实 `not_computed`；需要真实成本模型或人工填写才能升级为 `computed`。
- **尚需人工/实验验证**：所有"critical/major" CriticFinding（essential-gene 风险、缺失对照、falsifiability 缺口）目前只是结构化标记，实际的生物学/实验验证仍需人工判断——这正是 Human Gate 存在的原因，系统从未自行"验证"过这些假设。
