D. Scientific Credibility Notes
Every number in SimulationResult.endpoints carries source_type="model_output"; no LLM call exists anywhere in harness/virtual_cell/ (verified by grep).
Model domain: e_coli_core covers only 137 genes of central carbon metabolism. aroG/trpE/tnaA (the actual trp-pathway engineering targets) are genuinely out of domain — the E2E deliberately uses ppc (a real, single-GPR anaplerotic gene) instead of pretending to predict tryptophan titer.
Intervention mapping: gene knockouts use cobrapy's real gene-protein-reaction logic — this caught a real error in the pre-existing hand-written hint table (ptsG knockout does not block GLCpts under this model's GPR, because of isozyme redundancy; the old hint table wrongly asserted it would).
Uncertainty: FBA is a deterministic LP solve — every endpoint's confidence_status is unavailable, never a fabricated probability.
Baseline protocol: comparisons require identical model/version/artifact-hash/initial-state/solver; a mismatch produces invalid_comparison, never a number.
Governance: Level 3-5 model updates are structurally blocked (ImmutableFieldError-backed + explicit guard) without a ModelUpdateDecision row; Level 1 may auto-apply.

G. Residual Gaps (not "future work" hand-waving — concrete, with cause and consequence)
vEcoli whole-cell model is not runnable. Cause: bundled .venv is Linux-only; WSL exists but has no vEcoli checkout/ParCa sim_data. Consequence: no time-dynamics, expression/resource-competition, or whole-cell endpoint can ever be computed this round — router.py and ModelRegistryEntry honestly report this every time. Next step: build/configure vEcoli inside WSL (a substantial, long-running undertaking — ParCa alone is compute- and time-heavy) — this is the kind of real blocker Section 17 anticipates; I did not attempt it without confirming the time/resource cost with you first.
No kinetic/resource-allocation (ME-model) adapter exists at all — kinetic_resource has no artifact in this repo or its dependencies; router.py correctly returns no_compatible_model for expression/resource-competition questions.
Multi-scenario replicate handling is structurally correct but untested against a real stochastic model — simulation_config.replicate_index/random_seed fields exist and the reviewer checks for single-replicate stochastic runs, but since gem_fba is deterministic, no test exercises >1 real replicate.
CrossModalConsistencyReport (doc06 §7) was not built — Phase 3's multi-omics boundary work was scoped down to scalar phenotype endpoints (growth/uptake/secretion) reusing Observation directly; no transcript/protein/metabolite consistency-checking object exists. Consequence: any future omics ingestion needs this before Problem 6 can claim even the "registration + QC + conflict flagging" floor doc06 §7 sets.
Combination/multi-gene perturbation scenarios (S2/S3/S4 of doc06 §6.1) are supported by merge_compiled_bounds's conflict detection but only exercised for single-gene S0/S1 in tests.
Full browser/DOM verification of web/virtual_cell.html was not performed (see §F) — API-level correctness is proven, DOM rendering is reviewed but not screenshotted.
No static type-checker or linter is actually installed in this environment (pyrightconfig.json exists but no pyright/ruff/mypy in requirements.txt or the venv) — I did not install new tooling unprompted; all new code follows the repo's existing type-hint conventions but was not machine-checked.
