# 7.18 小组会会议报告

会议日期：2026-07-18  
会议主题：E. coli 虚拟细胞建模、合成生物学 Agent 原型、下周实验安排  

## 1. 本次会议核心结论

本次讨论明确了当前项目分为两条主线：

1. 多组学扰动数据与虚拟细胞建模
2. 合成生物学 Agent 专家系统

暑期阶段不以完整建模为主要目标。当前数据量不足以支撑最终模型训练，更现实的目标是推进可识别性问题、扩大扰动维度、积累有效样本，并验证这些数据是否能提供超过批次效应的真实生物学信号。

Agent 方向被认为是近期更容易快速推进、可以形成原型的主线。其目标不是简单查文献，而是把合成生物学专家优化底盘、设计实验、调用工具、解释结果的思维流程拆解成模块化 workflow，并用大模型结合数据库和代码工具实现自然语言交互。

下周实验优先级调整为：

1. 代谢组流程和 LC-MS/HPLC-MS protocol 是当前最大瓶颈，优先推进。
2. PCR 继续跑通，但不宜让新人一开始承担过多。
3. KO 菌培养可以作为成熟管线继续扩展样本。
4. 工程菌发酵难度更高，涉及诱导、摇瓶/孔板、培养基、诱导剂和发酵条件，需要单独读文献并提前准备材料。

## 2. 多组学扰动模型主线

### 2.1 最终目标

最终希望建立一个从基因组扰动到分子表型再到产物滴度的模型：

基因型扰动 -> 蛋白组变化 -> 胞内/胞外代谢组变化 -> 目标产物滴度变化

模型最终应能在给定目标产物后，提出具体基因型改造建议，例如应改哪些基因、哪些位点、用什么扰动方式，从而指导合成生物学实验。

该模型的应用目标是优化产物产量，但更核心的科学问题是理解细胞内部的信息传递：基因型如何逐步映射到蛋白质层面、代谢组层面和最终表型。

### 2.2 对标范围

项目后续模型预测和改造建议主要对标 K-12 底盘上已有的理性改造结果。

不直接对标多轮定向进化或多轮诱导突变产生的极高产量菌株，原因是：

1. 多轮诱导突变会显著改变基因型背景。
2. 菌株可能已经大幅偏离 K-12，甚至难以视为同一可比底盘。
3. 这类结果难以还原具体因果机制，也不适合作为理性设计模型的直接 benchmark。

### 2.3 当前数据覆盖现状

E. coli 约有 4000 多个基因。当前蛋白组检测无法覆盖全部蛋白，主要可测到 2000 多个蛋白。

未测到蛋白的主要原因：

1. 单一培养条件下并非所有基因都表达。
2. 有些蛋白丰度太低，低于质谱检测灵敏度。
3. 有氧/厌氧、不同营养条件下表达谱会显著不同。

虽然蛋白数量没有全覆盖，但已测到的 2000 多个蛋白占 E. coli 总蛋白组质量的 95% 以上。这说明虽然存在未覆盖蛋白，但主量级蛋白组已经被覆盖，仍有建模价值。

### 2.4 现有全细胞模型 baseline

会议提到现有最重要的机理模型参考是 Covert 组的全细胞建模工作：

1. 2012 年支原体全细胞模型  
   将细胞拆成 28 个子模块，不同模块使用不同数学表示，包括 ODE、随机过程、GEM 等，并以约 1 秒为步长更新细胞状态。

2. 2020 年 E. coli 扩展模型  
   扩展到 E. coli 后仅覆盖约 43% 基因，仍有 57% 基因无法覆盖。其主要意义在于 deep curation，即整合公开数据、参数化模型，并发现不同数据集之间的矛盾和质量问题。

现阶段 E. coli 尚没有特别完整的深度学习全细胞扰动模型。因此，现有机理模型可作为 baseline，但项目目标是建立结合多组学扰动数据和生物学先验的可学习模型。

### 2.5 当前最关键问题：可识别性

暑期建模主线的现实目标是推进 identifiability，即可识别性问题。

核心问题是：在当前扰动设计和仪器精度下，数据中是否能观察到超越批次效应和实验噪音的真实扰动信号。

需要比较的扰动类型包括：

1. CRISPRi 单基因敲低
2. ASKA 过表达
3. 多基因扰动工程菌
4. 主动构建的目标基因扰动

不同扰动类型的信息量可能不同：

1. CRISPRi 敲低可能被细胞冗余机制或同工酶覆盖，代谢表型可能不明显。
2. ASKA 过表达可能产生更强的信号，因为过表达会抢占细胞资源，形成 resource burden。
3. 多基因扰动可能更容易观察到超过批次效应的信号。

当前首要任务不是训练模型，而是通过更多扰动类型和更多样本判断哪些实验设计最能增加信息维度。

### 2.6 批次效应问题

现有单基因 KO 数据中，批次效应可能大于生物学扰动信号。会议中提到人类细胞中 1000 多个单基因 KO 蛋白组数据的主要差异可能来自板间差异，而不是 KO 本身。

因此项目需要解决：

1. 如何通过更多样本平均噪音。
2. 如何跨批次观察稳定信号。
3. 如何判断某些蛋白或通路变化是否显著。
4. 如何证明数据具有统计学意义和生物学可解释性。

可参考的思路是大规模 KO 蛋白组研究中，对每个蛋白在大量样本中整体比较，以降低噪音并提高显著信号的可见性。

### 2.7 建模路线

未来模型不应是纯数据驱动。由于蛋白组和代谢组样本成本极高，无法达到类似大语言模型训练所需的数据规模。

因此模型应结合生物学先验和深度学习：

1. 基因扰动 embedding
2. 基因到蛋白组扰动的映射
3. 蛋白组到代谢组扰动的映射
4. 代谢组到产物滴度的映射
5. 蛋白-蛋白互作图作为先验，例如 STRING database
6. 基因-基因关系或共表达图作为先验，例如 E. coli 转录组或 gene-gene relation 数据
7. 酶-代谢物关系和代谢网络作为强物理先验
8. GEM/FBA 代谢网络与图神经网络结合

只有当可识别性和统计学显著性被证明后，才进入正式模型训练阶段。

## 3. 合成生物学 Agent 主线

### 3.1 Agent 的定位

Agent 是独立于当前虚拟细胞模型的主线，可以先用现成数据库、文献和工具运行。

长期目标是：当虚拟细胞模型建好后，将其作为 Agent 可调用的一个模块，用于辅助实验设计。

短期目标是：构建一个合成生物学专家系统，使其能够根据目标产物、底盘和底物，给出工程菌设计方案、实验设计建议和下一步优化方向。

Agent 不只是替代查文献，而是要完成：

1. 理解目标产物和底盘。
2. 检索和解析相关文献。
3. 还原专家设计逻辑。
4. 调用代谢网络、FBA/GEM、数据库、蛋白功能、通路分析等工具。
5. 输出自然语言结论和结构化实验建议。
6. 隐藏代码细节，让无代码经验的合成生物学研究者也能使用。

### 3.2 使用模型与运行方式

会议提到优先使用 Kimi K3 作为 Agent 推理模型，原因是：

1. 性价比高。
2. 有 API 可直接调用。
3. 长任务稳定性较好。
4. 支持 swarm/orchestration 类多 Agent 调度能力。

Agent 可采用主 Agent 调度多个子 Agent 的结构。主 Agent 负责整体任务规划和结果整合，子 Agent 可分别负责文献解析、通路分析、工具调用、实验条件抽取等任务。不同子 Agent 的上下文可隔离。

### 3.3 Agent 原型开发的三件事

会议明确 Agent 当前要先产出两份方案进行讨论，其中学生侧和老师侧各自提出方案。方案需要回答三件事：

1. 初期需要开发哪些核心模块  
   不要求一开始覆盖全部合成生物学流程，但要覆盖最重要、最常用、最能形成原型闭环的模块。

2. Workflow 如何组织  
   需要说明模块之间哪些是串行关系，哪些是并行关系，哪些是按优先级调用，哪些由 Agent 根据任务动态选择。

3. 如何逆向解析文献  
   给定一篇关于某个底物到某个产物优化的合成生物学论文，需要标准化拆解出专家的设计逻辑、实验步骤、工具使用、条件设置、结果解释和下一步决策。

### 3.4 模块化思路

会议中讨论了多个可能模块。初期模块可以从合成生物学专家实际会调用的分析步骤出发，而不是强行从组学分类出发。

可能的核心模块包括：

1. 目标产物与底物定义模块  
   明确目标产物、底物、是否从头合成、是否外源喂底物、是否使用 K-12 底盘。

2. 目标通路识别模块  
   从文献或数据库中找到底物到产物的代谢通路，识别中间产物、反应步骤、对应酶和对应基因。

3. 限速酶识别与优化模块  
   判断通路中哪些酶可能限制产量，提出过表达、RBS 调控、启动子优化、蛋白工程、理性突变、变构位点改造等策略。

4. 竞争旁路抑制模块  
   识别中间产物可能流向的竞争通路，并建议 KO、CRISPRi、CRISPR/Cas 或启动子调控等方式减少副产物流。

5. 碳流分配与全局代谢模块  
   使用 FBA/GEM 等工具预测敲除或过表达后 flux 的变化，判断碳流是否更集中于目标产物。

6. 表达调控模块  
   涉及启动子强度、RBS、诱导系统、mRNA 丰度、翻译效率等。

7. 蛋白质工程模块  
   针对关键酶的活性、稳定性、底物特异性、反馈抑制和变构调控进行优化。

8. 培养基与诱导条件模块  
   抽取并比较培养基、诱导剂、诱导时机、诱导浓度、发酵阶段条件、金属离子、辅因子等信息。

9. 发酵与全细胞催化模块  
   关注培养方式、摇瓶或孔板、好氧条件、发酵时间、取样时间、产物检测方式等。

10. 证据库与参考案例模块  
    将已解析文献沉淀为可检索案例库，为 Agent 后续推理提供参考。

### 3.5 文献逆向解析标准

后续每篇合成生物学文献应尽量抽取以下信息：

1. 目标产物
2. 底盘菌株
3. 底物来源：从头合成或外源喂底物
4. 目标通路及中间产物
5. 涉及基因、酶和反应
6. 改造类型：KO、敲低、过表达、启动子替换、RBS 调控、蛋白突变、路径引入等
7. 为什么选择这些改造
8. 每一步改造后的产量、滴度、得率或生产速率变化
9. 培养基、诱导剂、诱导时机和诱导浓度
10. 发酵方式、取样时间和检测方法
11. 作者如何根据前一步结果设计下一步实验
12. 失败或瓶颈的解释
13. 可复用到 Agent 的模块和工具调用逻辑

文献解析要形成标准输入输出协议，保证不同人解析出的结果可比较、可合并、可被 Agent 读取。

### 3.6 Agent 评估与迭代方式

Agent 迭代不应只看它是否复述文献，而应比较有无 Agent 框架时推理质量的差异。

可行评估方式：

1. 收集一批合成生物学产物优化文献。
2. 将大部分文献解析为参考案例，供 Agent 使用。
3. 保留一部分文献作为测试集。
4. 对同一任务分别运行：
   - 只有通用 prompt 的大模型
   - 带有 Agent harness、模块、数据库和工具调用能力的大模型
5. 比较两者是否能提出更接近专家论文设计思路的方案。

即使大模型预训练中可能见过部分论文，仍可通过消融比较验证 Agent 框架是否提升推理质量。

## 4. 数据库与先验资源

### 4.1 EcoCyc / EcoCyc 派生表

会议提到 EcoCyc 是 E. coli 领域长期人工策展数据库，包含大量基因、蛋白、通路和文献证据。其内容来自多年人工整理的 E. coli 文献。

当前已有的 H1 表格可视为从 EcoCyc 中蒸馏出的基因-蛋白功能层面信息，适合作为入门资料，但需要注意：

1. 表格多标注的是蛋白主要功能。
2. 同一个蛋白可能有多个功能。
3. 蛋白在不同细胞位置和条件下可能扮演不同角色。

### 4.2 ecoKG

ecoKG 已经整理了 E. coli 基因、功能、相关通路等信息，可作为 Agent 和建模的基础知识库之一。

### 4.3 STRING

STRING database 可提供蛋白-蛋白互作关系，可作为蛋白组层面的图先验。

### 4.4 合成生物学文献库

EcoCyc 主要是 E. coli 基础生物学研究文献，而 Agent 需要的是合成生物学产物优化文献。两者是正交但互补的资源。

后续需要自建合成生物学文献数据库，重点记录：

1. 针对 K-12 或相关底盘的产物优化案例。
2. 每篇论文的设计逻辑和实验流程。
3. 产物、底物、通路、基因、酶、培养和发酵条件。
4. 可复用的模块化决策模式。

## 5. 下周实验安排

### 5.1 总体优先级

下周不要同时铺太多任务导致每件事都做不好。优先把瓶颈任务跑通，并把成熟流程交给更多人参与。

优先级如下：

1. 代谢组 LC-MS/HPLC-MS protocol 设计与验证
2. PCR 流程跑通
3. KO 菌培养扩展
4. 工程菌发酵准备和小规模推进
5. Agent 原型方案设计

### 5.2 KO 菌培养

KO 菌培养流程相对成熟，可以继续做更多样本。目标是扩大数据量，让每个蛋白在更多样本和批次中被观察，从而帮助降低噪音、评估批次效应并寻找稳定扰动信号。

初步安排：

1. KO 培养可由有经验成员带新人一起做。
2. 流程参考上一次 KO 菌实验。
3. 每个 KO 初步考虑两个重复。
4. 若人手允许，可以继续扩展新一批 KO 样本。

### 5.3 PCR

PCR 下周继续推进，但优先由已有基础的人先跑通。新人可以后续学习，不建议一开始参与过多以影响流程稳定性。

### 5.4 工程菌发酵

工程菌发酵比 KO 培养复杂，主要差异在于：

1. 发酵前需要诱导表达。
2. 不同论文使用不同启动子和诱导剂，例如 IPTG 等。
3. 实验室不一定已有所有诱导剂，需要提前确认并采购或借用。
4. 需要根据文献模拟对应条件，包括培养基、诱导剂、诱导时间、摇瓶或孔板发酵方式。
5. 若使用摇瓶，摇床容量有限，需要提前规划样本数。
6. 若使用 96 孔板发酵，需要明确通气和发酵条件。

会议中提到部分诱导剂可能需要向曾老师团队借用。

### 5.5 代谢组

代谢组是当前最大技术瓶颈。下周应重点研究并确定成熟可上机的 LC-MS/HPLC-MS protocol。

需要明确：

1. 胞外代谢组和胞内代谢组分别如何前处理。
2. 取样后是否需要立即处理，哪些步骤可以冻结暂停。
3. 上样量。
4. 方法时长。
5. 上机条件。
6. 是否采用真空过滤处理胞内代谢物。
7. 冷甲醇淬灭方案是否会导致代谢物泄漏。
8. 与 HPLC 平台和 LC-MS 平台的兼容性。

会议中提到，之前 HPLC 问题可能不是系统堵塞本身，而是接废液/收集瓶颜色或连接方式错误；后续应记录进实验报告，避免重复错误。

### 5.6 材料采购

下周需要用到的材料应尽快汇总，立即启动采购流程。

需要提前确认：

1. 工程菌诱导剂是否已有。
2. 培养基组分是否齐全。
3. 发酵耗材是否足够。
4. 代谢组前处理耗材是否足够。
5. 真空过滤相关耗材是否齐全。
6. 摇瓶、孔板、滤膜、上样瓶等耗材是否足够。

## 6. 人员与分工

会议中涉及的分工方向如下，具体名单后续可再确认：

1. Agent 方案  
   兆琨、赫颖、怡璇为主，兆琨和赫颖提供合成生物学思路，怡璇提供 Agent 推理和 workflow 思路。老师侧也会独立给出一份方案。

2. KO 培养  
   由熟悉 KO 流程的人带队，新人可参与。该流程相对成熟，适合多人共同扩展样本量。

3. 工程菌发酵  
   需要单独读文献、确认诱导和发酵条件。工程菌发酵流程比 KO 更复杂，应由更熟悉实验的人主导。

4. PCR  
   先由已有基础成员跑通，其他人后续再学习。

5. 代谢组 protocol  
   重点由相关同学和老师并行调研，之后汇总方案。目标是形成成熟可执行的 LC-MS/HPLC-MS 前处理和上机流程。

## 7. 风险与待解决问题

### 7.1 数据层面

1. 当前数据量不足，不适合直接进入最终模型训练。
2. 扰动信号可能被批次效应掩盖。
3. 单基因 KO 可能信号太弱。
4. CRISPRi 敲低可能因冗余机制或同工酶导致代谢表型不明显。
5. ASKA 过表达可能产生 resource burden，需要区分目标效应和资源负担效应。

### 7.2 技术层面

1. 代谢组前处理尚未完全成熟。
2. 胞内代谢组样本处理难度较高。
3. 冷甲醇方案可能存在代谢物泄漏风险。
4. 真空过滤方案需要进一步验证。
5. 工程菌诱导和发酵条件依赖具体文献，不能简单套用 KO 流程。

### 7.3 Agent 层面

1. 需要明确标准模块和标准输入输出协议。
2. 不同人解析同一篇文献可能得出不同结构，需要统一解析模板。
3. 模块之间的关系可能不是单纯串行，可能包含并行、优先级和动态调度。
4. 需要建立合成生物学文献库，而不是只依赖 EcoCyc。
5. 需要设计评估方式证明 Agent harness 的增益。

## 9. 后续判断标准

### 9.1 多组学数据是否值得继续 scale up

需要回答：

1. 新扰动类型是否带来超过批次效应的信号。
2. 蛋白组和代谢组是否能观察到可解释变化。
3. 是否能进行通路层面的统计分析。
4. 是否能支持后续生物学发现。
5. 哪类扰动最适合扩大样本规模。

### 9.2 Agent 原型是否有效

需要回答：

1. 是否能从文献中稳定抽取目标产物、通路、基因、酶、改造方式和实验条件。

3. 是否能调用工具并输出可理解的自然语言结论。
4. 是否能比普通大模型 prompt 给出更接近专家设计逻辑的方案。
5. 是否能形成可迭代的 workflow。
