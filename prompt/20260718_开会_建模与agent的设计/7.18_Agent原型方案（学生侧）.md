## 一、背景与问题

### 1.1 项目背景

项目的更深目标是理解细胞：基因型如何一步步映射到蛋白组、代谢组，再到表型（对应会议纪要 2.1）。虚拟细胞建模和 Agent 是朝这个目标走的两条正交但同向的路径：建模路线从多组学扰动数据出发拟合这条映射关系，Agent 路线从合成生物学专家已经验证过的因果推理出发，把"为什么这么改"的机理逻辑显式拆解成可复用的模块化 workflow。两条路线不冲突，长期会汇合：虚拟细胞模型成熟后，可以作为 Agent 内部一个可调用的预测模块，替换掉现在依赖的计算工具。

### 1.2 要解决的问题

合成生物学专家做代谢工程改造时，脑子里其实在做一件相对固定的事：拿到目标产物 → 查通路 → 找关键节点 → 判断怎么改 → 定培养和发酵条件 → 设计验证方式。但这套经验目前高度依赖个人查文献、个人判断，存在几个具体问题：

- 查文献效率低，专家凭个人熟悉程度决定看哪些论文，容易漏掉相关但不熟悉领域的先例。
- 单人经验难以覆盖所有可能的设计动作（限速酶识别、竞争支路阻断、表达调控、蛋白质工程……），容易带入个人偏好。
- 新手难以快速复用专家的隐性决策逻辑，只能看到论文的结果（"改了哪个基因"），看不到决策链条本身。
- 计算工具（FBA、结构预测等）产出的是预测值，容易被误当成和实测数据同等可信的证据。

Agent 要做的不是替代查文献，而是把这条决策链条模块化、可检索、可复用，并且明确区分"实测证据"和"计算预测"，让没有代码经验的合成生物学研究者也能通过自然语言拿到有依据的实验设计建议。

### 1.3 为什么只做理性设计

只做理性设计（每一步改造都能追溯到通路、酶、调控上的具体机理原因），是刻意选定的范围，不是能力短板，理由与会议纪要 2.2 节"对标范围"一致：项目不对标多轮定向进化/诱导突变产生的高产菌株，因为那类菌株基因型已大幅偏离 K-12、因果机制难以还原，不适合作为理性设计的参照。进化涌现的突变落在通量分支点、事前无法理性预测，本身也不可机理解释，这与"理解细胞"这个总目标是一致的——Agent 只处理"为什么这么改"能说清楚的那部分设计。

### 1.4 范围界定

| 维度 | 初版范围 |
|---|---|
| 产物/底物 | 单产物、单底物、单条通路 |
| 产物类型 | 天然产物（解除调控 + 通量集中）、非天然产物（通路预测 + 宿主改造） |
| 设计类型 | 理性设计（可机理解释） |
| 底盘 | E. coli K-12 |

## 二、目标与预期贡献

### 2.1 总体目标

给定目标产物、底盘（默认 K-12）、底物，Agent 输出工程菌设计方案、实验设计建议和下一步优化方向。用户用自然语言提问，系统输出人能直接看懂的实验设计：改哪几个基因、用什么方式改、发酵条件如何、每条建议的依据和预测效果；所有工具调用（数据库查询、FBA、通路图检索）在后端运行，对用户不可见。

### 2.2 相对直接使用大模型的预期增益（假设，待验证）

在动手做模块之前，先要想清楚这套系统凭什么比直接把问题丢给大模型更好，这决定了哪些模块值得优先做实。候选增益来源列在下面，哪一项为主由第五章的消融实验判定，不预设结论：

| 候选来源 | 说明 |
|---|---|
| 接地数字 | 理论得率、FBA 通量、基因必需性这类，裸模型仅能凭记忆；系统用工具算出真值 |
| 覆盖完备 | 对每个分支点逐一过一遍全部设计动作，不受单人经验偏好限制 |
| 精确调取先验 | 某个残基、某个 Km、某个启动子强度，通过决策记录/规则库检索精确取出 |
| 推理脚手架 | 把任务分解成专家的决策步骤，逐步接地 |
| 规则迁移 | 一类产物抽出的规则，用到另一类产物问题上（如某产物的驱动力规则用到另一产物） |

一个待检验的判断：通用规则（解除反馈、敲竞争支、平衡表达）大多是教科书级，base model 可能已经掌握，增益更可能集中在前三项（接地、完备、精确调取），而非后两项（通用推理、迁移）。这个判断直接影响工程优先级：如果增益主要来自"接地"和"精确调取"，那么第一版最值得投入的是"工具真值计算"和"证据检索"，而不是让 Agent 做更复杂的通用推理。

### 2.3 分阶段目标

- **第一版（MVP）**：跑通"产物 → 通路 → 关键节点 → 改造方案 → report"最小闭环，覆盖最核心的 7 个模块（见第四章），用真实工具/数据库替代占位输出。
- **第二版**：补齐表达调控、蛋白质工程、培养与发酵条件、结果反馈迭代等模块，扩展语料库规模。

## 三、生物学背景知识手册

这一节整理工作流中会用到的生物学与计算工具概念，供零生物背景的读者在阅读第四、五章时随时查阅，不需要通读。

### 3.1 最基础的几个词

- **基因（gene）**：DNA 上的一段"配方"，写着怎么造一个蛋白质。"改造基因"本质上是在改这份配方，或者决定要不要执行它。
- **蛋白质 / 酶（protein / enzyme）**：基因这份配方做出来的产品。酶是一类特殊蛋白质，作用是催化（加速）细胞里的化学反应，把一个分子变成另一个分子。
- **代谢物（metabolite）**：细胞里的各种小分子物质，糖、氨基酸，以及我们要的目标产物，都是代谢物。
- **代谢通路（pathway）**：底物变成产物要经过一连串反应，像一条工厂流水线，每一步反应由一个酶负责。
- **底物（substrate）**：进入这条流水线的原料，比如葡萄糖。
- **产物（product）**：流水线终点想要的东西，比如色氨酸。
- **中间产物（intermediate）**：流水线中间还没走完的半成品。
- **表达（expression）**：细胞"读取"基因配方、实际生产出对应蛋白质的过程和量的多少。"过表达"就是让细胞多造这个蛋白。
- **底盘 / 宿主（chassis / host）**：承载这条流水线的宿主细胞，本项目特指 E. coli K-12 这个菌株背景。

### 3.2 改造动作

- **敲除（knockout, KO）**：把某个基因整个删掉，细胞完全不能再造对应的酶。
- **敲低（knockdown）**：不删基因，但用某种手段（如 CRISPRi）压低它的表达量，酶变少但没完全消失。
- **过表达（overexpression）**：让细胞造更多某个酶，通常通过换更强的启动子或增加基因拷贝数实现。
- **基因插入（gene insertion）**：把一个原本没有的新基因放进细胞里，比如从别的物种搬一个酶过来（"异源"表达）。
- **点突变（point mutation）**：不删不加基因，只改这个基因里一两个"字母"（碱基），让做出来的蛋白质某个氨基酸变了，可能改变它的活性或让它不再受某种抑制。
- **启动子替换（promoter swap）**：启动子相当于基因前面的"开关+调速器"，换启动子就是换一个表达强度不同的开关，调的是"造多少 mRNA"这一步。
- **RBS 调控**：RBS（核糖体结合位点）决定这段 mRNA 被翻译成蛋白质的效率，调 RBS 调的是"mRNA 造多少蛋白质"这一步，和调启动子作用在不同层级。
- **CRISPRi**：不删除基因、只是用类似"贴封条"的机制暂时压低表达的技术，效果类似可逆的敲低。

### 3.3 调控与限速相关概念

- **反馈抑制（feedback inhibition）**：流水线终点产物太多了，直接回头"捂住"最上游的酶让它减速，是细胞自带的刹车机制。改造时常常要故意打破这个刹车（用抗性突变），让产物能持续积累而不被自我抑制。
- **前馈抑制（feedforward inhibition）**：不是终产物抑制上游，而是某个中间产物"提前"抑制它下游的酶，比反馈抑制更隐蔽、容易被忽略。
- **限速酶 / 限速节点（rate-limiting step）**：流水线里最慢的那一步，决定了整条线的产出速度，类似瓶颈工位。
- **分支节点（branch point）**：某个中间产物有多条去路（一部分流向目标产物，一部分流向细胞自身生长需要的其他物质），需要决定怎么分配。
- **辅因子 / 还原力（cofactor / reducing power，如 NADPH）**：很多酶反应除了底物，还需要额外的"能量/电子搬运工"分子参与，供应不够，反应也做不快。
- **竞争支路（competing pathway）**：跟目标产物抢原料的其他代谢路径，通常需要敲掉或削弱来把碳流集中到目标产物。
- **碳流（carbon flux）**：细胞里碳原子沿各条代谢路径流动的速率和方向，"让碳流集中到目标产物"就是希望更多原料的碳走到我们要的那条线上。

### 3.4 代谢工程常用指标

- **滴度（titer）**：培养体系里目标产物的最终浓度，如多少 g/L。
- **得率（yield）**：投入多少底物换来多少产物，如每消耗 1g 葡萄糖能产多少 g 目标产物（g/g）。
- **生产速率（productivity）**：单位时间产出多少产物。
- **理论得率（theoretical yield）**：在给定代谢网络下，从底物到产物在化学计量上能达到的最高得率上限，用 FBA 这类工具算出来的"天花板"，实际得率一般达不到理论值。

### 3.5 计算工具与模型概念

- **代谢网络模型（GEM, genome-scale metabolic model）**：把细胞里已知的所有代谢反应整理成一个大网络模型，可以用来做各种"如果这样改会怎样"的计算，iML1515 就是 E. coli K-12 的这样一个模型。
- **FBA（flux balance analysis，通量平衡分析）**：给定这个代谢网络和一些假设（比如细胞要长得快），计算出每条反应大概的流量分配，从而估计理论得率、判断某个基因是否必需。可以理解为"给工厂排产计划"的算法。
- **COBRApy**：让研究者用代码跑 FBA 等分析的软件包，是本方案里实际执行 FBA 计算的工具。
- **OptKnock**：在 FBA 基础上专门回答"敲掉哪些基因的组合，能让细胞不得不多产目标产物才能长好"这个问题的算法，输出"建议敲除的基因组合"，但这只是计算预测，需要实验验证（标为"软证据"）。
- **必需性分析（essentiality analysis）**：判断某个基因被敲掉后细胞是否还能存活/正常生长，避免给出一个会让菌株直接死掉的敲除方案。
- **反应热力学（ΔG，如 eQuilibrator 计算）**：判断一个化学反应在细胞条件下是"顺着走"（放能、容易发生）还是"逆着走"（需要额外驱动力），用来判断某些反应是否需要额外设计驱动力。
- **结构预测（AlphaFold/ESMFold）**：不用做实验，靠计算直接预测一个蛋白质的三维空间形状，形状决定了它的功能和会不会被某个小分子结合抑制。
- **分子对接（docking）**：计算预测一个小分子（比如某个中间产物）能否、以多强的力度"贴合"到某个蛋白质的某个位置上，用来预测抑制/结合关系，同样是预测、需要实验确认（软证据）。
- **FoldX / ΔΔG**：预测某个点突变会让蛋白质稳定性变化多少，帮助判断一个"抗性突变"会不会同时把酶弄得不稳定。

### 3.6 数据库速查表

| 数据库/资源 | 存的是什么 | 我们用它查什么 |
|---|---|---|
| EcoCyc | 人工整理多年的 E. coli 基因、蛋白、通路、调控信息 | 通路结构、基因功能、已知调控关系 |
| KEGG | 多物种通用的代谢通路和反应数据库 | 补充/交叉验证 EcoCyc 的通路信息 |
| RegulonDB / iModulon | E. coli 转录调控网络、共表达调控模块 | 判断基因是否受转录调控、启动子强度参考 |
| BRENDA | 酶学数据库，收录各种酶的动力学参数 | 查 Km/kcat，判断哪个酶动力学上更可能是限速步骤 |
| UniProt / PDB / AlphaFold DB | 蛋白质序列、已解析结构、预测结构 | 结构分析、判断突变位置、docking 输入 |
| STRING | 蛋白-蛋白相互作用网络 | 判断蛋白间是否有已知互作，辅助调控关系分析 |
| iML1515（存于 BiGG 数据库） | E. coli K-12 的基因组尺度代谢网络模型 | FBA/OptKnock 计算的底座模型 |

### 3.7 检测技术

- **LC-MS（液相色谱-质谱）**：先用液相色谱把样品里成千上万种小分子按物理化学性质分开，再用质谱给每个分子"称重+验明身份"，从而知道样品里有哪些代谢物、各有多少。
- **HPLC（高效液相色谱）**：分离原理与 LC-MS 类似，但通常搭配更简单的检测器，适合已知目标物定量，速度快但不如 LC-MS 能鉴定未知物。
- **proteomics（蛋白质组学）**：一次性测量细胞里尽可能多的蛋白质种类和数量，通常靠质谱完成。
- **metabolomics（代谢组学）**：一次性测量细胞里尽可能多的小分子代谢物种类和数量，是 LC-MS/HPLC protocol 要解决的检测对象。

## 四、方法与材料

### 4.1 设计原则

- **先闭环，再扩展**：先跑通一条最小可行的"产物 → 方案 → report"闭环，再把闭环内的分析步骤逐步替换为独立模块，而不是一开始铺开全部模块。
- **从专家实际调用顺序出发，而不是从组学分类出发**：模块划分参考专家做代谢工程时的实际决策顺序，而非"基因组学模块/蛋白组学模块/代谢组学模块"这种学科切法。组学作为横切证据来源存在（多个模块都可从组学取证据，后续也可作为用户上传数据的可选输入），但不单独成模块。
- **证据优先于计算**：凡是文献里有直接先例的改造，优先采信文献证据；只有文献空白或矛盾时才依赖 FBA/GEM 等计算推理去补空，且计算推理产出标注为"假设，需实测确认"，不与实测证据同权。
- **隐藏代码细节**：所有工具调用对用户不可见，用户只看到自然语言结论和结构化实验建议。

### 4.2 MVP 五步闭环

```
① 任务理解/需求解析
   输入：用户自然语言描述
   输出：product, host, substrate, goal（结构化字段）
        ↓
② 文献检索与解析
   动作：检索该 product/substrate 相关的合成生物学论文，
        按 4.5 节 DDR 协议标准化拆解设计逻辑、实验步骤、工具使用、条件设置、结果解释、下一步决策
   输出：DDR 记录（设计动作/靶标/触发/证据/证据分级/理由性质/实现方式/结果/规则）
        ↓
③ 代谢通路分析
   动作：查询 EcoCyc/KEGG（天然产物）或 RetroPath2/novoStoic（非天然产物），
        用 COBRApy 算理论得率，获得 substrate → intermediate → product 路径
   输出：pathway map + 理论得率
        ↓
④ 工程改造推理
   动作：基于②③的证据，判断每个关键基因该敲除？过表达？调控？
        证据字段强制非空——任何一条改造建议必须挂到一条论文先例、一次工具预测、或一条数据库记录上，
        并标明证据分级，否则不进入设计方案
        ↓
⑤ 生成实验方案
   输出：菌株设计、培养条件、验证方法、每条建议的证据出处与分级 → 汇总为 report
```

### 4.4 系统工程架构

**总体架构：**

```
用户自然语言输入
      ↓
主 Agent（orchestrator，持有 TaskState 状态机）
      ├─ 子 Agent：文献解析（读论文，产出 DDR 记录）
      ├─ 子 Agent：通路/节点分析（调用 M3/M4/M5/M10 对应工具）
      ├─ 子 Agent：工具调用层（COBRApy、EcoCyc/KEGG 查询、BRENDA 查询等的统一封装）
      └─ 子 Agent：实验条件抽取（M11/M12/M13）
      ↓
知识/数据层：DDR 语料库 + 规则库 + 模块注册表 + 产物-通路-前体图
      ↓
结构化设计报告（自然语言 + 每条建议的证据出处与分级）
```

主 Agent 负责任务规划与结果整合，子 Agent 上下文相互隔离，只在某个子任务需要深读一篇论文或一个酶结构、需要独立上下文空间时才拆出子 Agent，不做大规模并行子任务的滥用。推理模型优先使用 Kimi K3（性价比、API 可用性、长任务稳定性、支持多 Agent 调度）。

**技术选型（标注待定项）：**

- 编排方式：**待定**——自己写一个轻量状态机（每个 Phase 是一个函数，state 以 JSON 在函数间传递），还是引入现成的 agent 编排框架。建议第一版先用最简单的"Python 函数链 + JSON state"手写实现，不引入额外框架依赖，等流程稳定后再评估是否迁移，避免过早绑定一个还不熟悉的框架拖慢原型速度。
- 语料检索：第一版语料量小（个位数到几十篇）时用关键词/结构化字段过滤即可；语料库扩展到上百篇后再引入 embedding + 向量库做语义相似检索，是刻意的分阶段决定，避免为几十条记录的检索问题过度设计。
- 工具调用层：每个外部工具/数据库查询都包一层统一的 wrapper 函数，返回统一格式（数值/结论 + 来源 + 证据分级标记），方便以后换实现或加缓存。

**State 数据结构（贯穿全流程的核心状态，JSON 示意）：**

```json
{
  "task_id": "string",
  "phase": "Phase0 | Phase1 | ... | Phase7",
  "target": {
    "product": "string",
    "host": "E. coli K-12",
    "substrate": "string",
    "substrate_origin": "de_novo | fed_exogenous",
    "product_type": "natural | non_natural",
    "goal": "design_new | diagnose_bottleneck | optimize_existing"
  },
  "pathway": {
    "map": "...",
    "intermediates": ["..."],
    "theoretical_yield": {"value": 0.227, "unit": "g/g"}
  },
  "nodes": [
    {"type": "rate_limiting | branch | regulatory | resource", "target": "gene/enzyme", "evidence": []}
  ],
  "interventions": [
    {
      "module": "M7",
      "target": "gene/enzyme",
      "action": "KO | knockdown | overexpression | insertion | point_mutation | promoter_swap | RBS_tuning",
      "evidence": [{"source": "string", "grade": "hard | soft", "value": "string"}],
      "confidence": 0.0,
      "needs_wetlab_validation": true
    }
  ],
  "culture_conditions": {},
  "validation_plan": {},
  "ddr_refs": ["ddr_id 列表，本次设计参考了哪些历史案例"]

```

**模块调用接口规格（伪代码，非最终代码）：**

```
run_module(module_id, state) -> ModuleOutput

ModuleOutput = {
  proposals: [...],          # 提议的改动
  evidence: [...],           # 每条改动必须挂证据，字段强制非空
  confidence: float,
  needs_validation: bool
}
```

失败兜底策略：外部工具调用超时/失败时，模块输出标记 `status: degraded`，orchestrator 决定是跳过该模块、使用缓存结果，还是转入人工介入队列；数据库查询无结果时按 4.6 节的动态调度规则做 fallback（如 EcoCyc 查不到转向 KEGG）。

**标准输入输出契约**：所有模块统一用"输入：靶标规格、当前设计状态、相关通路子图；输出：提议的改动、每条改动的证据及分级、量化预测、置信度、需实测的点"这套契约，其中"证据"字段强制非空——任何一条改造建议必须挂到一条论文先例、一次工具预测、或一条数据库记录上，并标明证据分级，否则不进入设计方案。M10 的接口刻意与未来"虚拟细胞模型"的输出对齐：当前用 COBRApy/FBA 算 flux 变化，接口格式与虚拟细胞建模主线最终产出的"基因型→蛋白组→代谢组→滴度"预测结果保持一致，后续虚拟细胞模型验证成熟后可直接替换 M10 的计算后端，不改变上下游模块的调用方式。

### 4.5 文献逆向解析协议（DDR：Design Decision Record）

一篇底盘改造论文可看成一条决策链：想产什么 → 观察到什么 → 提出什么假设 → 拿什么证据 → 做了什么改动 → 怎么验证 → 结果多少。逆向工程抽的是这条链和背后能迁移的规则，不是"改了哪几个基因"这张结果清单——清单只对这一篇有效，规则可用到下一个产物。

不是所有论文都有干净的决策链——很多改造的真实理由是"上一篇这么做""筛库筛出来的"，不是机理推断。硬把这类论文凑出规则会污染规则库，因此协议里显式记录理由性质，不回避筛选和事后合理化的情况：

| 字段 | 含义 |
|---|---|
| 设计动作 | 属于哪个模块（对齐 4.3 节 M1-M14） |
| 靶标 | 动了哪个基因/酶/通路/条件 |
| 触发 | 什么观察或推理触发了这一步 |
| 证据 | 具体证据，含出处和数值 |
| 证据分级 | 硬（实测：结构、动力学、已验证改造结果；或化学计量：理论得率、通量、必需性）/ 软（预测：OptKnock、docking、ΔΔG，待实测确认） |
| 理由性质 | 机理推断 / 文献类比 / 现成可得 / 筛选得来 / 事后合理化存疑 |
| 备选 | 考虑过又放弃的方案及原因 |
| 实现方式 | KO / CRISPRi / 过表达 / 点突变 / 启动子 / 培养基 等 |
| 结果 | 量化结果（滴度/得率，前→后） |
| 规则 | 从这一步抽象出的可泛化启发式（仅当理由性质为机理推断或可靠文献类比时才写） |

"证据分级"和"理由性质"两个字段是防止规则库被污染的核心机制：前者防止把不可靠的工具预测当硬证据，后者防止把编造的理由当成可泛化规则记录下来。

**抽取流程**：先手工深度策展 3-5 篇 → 每篇沿决策链切成若干条 DDR → 规则字段两人独立写、再对齐统一口径（解决"同一篇不同人抽出来不一样"）→ 校准后作为示例让 Agent 半自动抽取剩余论文、人工抽检 → DDR 入语料库，可靠规则去重后进规则库。

**完整解析样例（色氨酸，Chen & Zeng 2018）**：选定这篇作为第一个跑通协议的样例，原因是决策链完整、理由多为机理推断（反馈+前馈+酶工程+异源替换），四条 DDR 串成一张决策图：

| 步骤 | 设计动作 | 触发与证据 | 证据分级 | 结果 | 抽出的规则 |
|---|---|---|---|---|---|
| 1 | 解除末端反馈（M4+M7） | Trp 对 committed 酶 TrpE 反馈抑制（已知） | 硬 | TrpE(S40F) 抗性突变 | 天然产物先查 committed 酶的末端反馈，用抗性突变解除 |
| 2 | 识别隐藏调控（M4） | 加大上游拷贝数不增产、中间体 anthranilate 积累；晶体结构显示 anthranilate 与产物 IGP 互作 | 硬(结构)+软(docking) | 体外确认非竞争抑制，IC50 0.70 mM | 中间体积累且加上游不增产时，查该中间体对下游酶的前馈抑制 |
| 3 | 理性突变去抑制（M9） | 结合位点紧邻催化位点 | 硬 | S60A 抗性升约 3 倍但比活下降 | 去抑制常有比活代价，记录 trade-off 并准备替代路线 |
| 4 | 异源酶替换（M7/M9） | A. niger 同工酶的 IGPS 被 anthranilate 前馈激活而非抑制 | 硬 | Trp 19→29 g/L，得率 0.15→0.18（理论上限 0.227） | 本源酶去抑制有代价时，跨物种筛反向调控的同工酶 |

Agent 面对新的天然产物，应遍历同构的这张图，在每个节点查库、跑工具接地，而不是直接背出"改哪几个基因"这个结果清单。

已解析文献按上述协议结构化后进入 **DDR 语料库**，从中蒸馏出的跨论文可泛化启发式（仅收录理由性质为"机理推断"或"可靠文献类比"的规则）进入 **规则库**，供各模块检索复用，是 M7 判断"文献先例 vs 计算推理"的直接数据来源；与 EcoCyc/KEGG 这类基础生物学知识库正交互补——M1-M4 主要查基础知识库定通路和功能，M5-M9 主要查 DDR 语料/规则库定改造方式。

### 4.6 Workflow 编排逻辑

**相位流程：**

```
Phase0 意图解析与靶标框定 (M1/M2, routing: 天然/非天然、新设计/诊断卡点/优化现有)
  → Phase1 通路解析 (M3)
  → Phase2 靶标分析 (M4/M5/M10 并行-sectioning)
  → Phase3 改造设计 (M7/M8/M9, 证据优先于计算、表达调控优先于蛋白质工程)
  → Phase4 集成筛选 (M14, evaluator-optimizer, 汇聚屏障)
  → Phase5 培养/发酵过程 (M11/M12)
  → Phase6 一致性采样 (parallel-voting) + 验证方案设计 (M13)
  → Phase7 输出设计报告
```

Phase3→Phase4 是汇聚屏障：必须拿到 Phase3 所有靶标改造方案后才做全局自洽检查（例如某个要敲除的竞争支路基因，是否恰好是下游某个限速反应的必需基因）。Phase4 是一个生成-评审回路：生成器（M3-M10 各模块）提出设计，评审器检查自洽性——要敲的基因是否是下游必需基因、证据是否齐备、软证据是否被误当硬证据使用——并筛掉仅表面合理的方案，不合格则打回 Phase2/Phase3 重来。

**编排关系一览：**

| 阶段/关系 | 归类 | 说明 |
|---|---|---|
| Phase0→Phase7 | 串行（prompt chaining） | 每一相位消费上一相位的输出，适合可稳定分解的固定流程 |
| M4 四类节点识别、M5 vs M10、文献解析 vs 数据库查询 | 并行（parallel-sectioning） | 互不依赖，可并行跑，结果合并后统一送入下一步 |
| Phase6 一致性采样 | 并行（parallel-voting） | 同一设计任务跑 N 次，对干预方案聚类，看哪些改造稳健收敛 |
| 文献先例 vs FBA 推理 | 优先级 | 证据优先，只有缺乏先例时才启用计算推理，且标为软证据 |
| M8 vs M9 | 优先级 | 表达调控成本低、周期短，优先于周期长、失败风险高的蛋白质工程 |
| M1/M2 后的路径选择 | 动态（routing） | 天然产物走解除调控+通量集中，非天然产物走通路预测+宿主改造 |
| M6/M9 是否触发 | 动态（orchestrator-worker） | 由 M4 的判断结果决定，不在默认路径中固定调用 |

## 五、预期结果

### 5.1 评估方式

不以"复现论文"为金标准——论文设计只是可行空间里的一个点，还被当年可得性和流行度带偏；若论文在训练语料里，裸模型也能复述。真正要看的是 Agent 能否生成有据的合理新颖设计、并筛掉不够好的候选，这一判断落在 Phase4 evaluator-optimizer 回路，最终由湿实验验证。

| 层 | 指标 |
|---|---|
| 过程 | 接地率（每条建议是否挂证据、分级是否正确）、覆盖完备（是否过完所有分支点×设计动作） |
| 能力 | 筛选能力（能否剔除弱证据/自相矛盾方案）、合理新颖（不在论文里但有据）、一致性（N 次采样收敛度） |
| 结果 | 湿实验验证——唯一金标准 |

复现率仅作 sanity check，不作主指标。具体执行方式：收集一批合成生物学产物优化文献，多数解析为 DDR 语料入库，保留一部分作为测试集；对测试集任务分别运行（a）仅通用 prompt 的大模型和（b）带有本方案 harness 的大模型，按上表三层指标比较差异，作为第 2.2 节增益假设的直接证据。

### 5.2 第一个端到端目标：色氨酸

理由：天然产物、有完整论文参照（Chen & Zeng 2018）、决策链丰富且多为机理推断，4.5 节已给出完整 DDR 示例可直接复用为验收基准。工具用 COBRApy + iML1515 + EcoCyc + BRENDA + docking，全部 CPU 可跑。

最低验收标准：

1. 输入"葡萄糖产色氨酸"，系统自动查出 trp 通路 + 分支点，给出最大理论得率（≈0.227 g/g）。
2. M4 查出 TrpE 末端反馈，提议抗性突变；检索到色氨酸 DDR 后主动核查 anthranilate 对 IGPS 的前馈抑制（裸模型基本给不出，是第 2.2 节增益假设的直接证据）。
3. M5 用 OptKnock 给出竞争支敲除集 + 必需性反查，结果标为软证据。
4. Phase6 一致性采样跑 20 次，报告哪些干预稳健收敛。
5. 输出一张人能看懂的设计表，每条带证据出处和分级。

达到这 5 条，即有一个可用原型，可拿去评审、并进入湿实验验证。
