# Knowledge & Evidence Layer 与整体 Agent 架构一致性审查与修复任务

## 背景

当前 Synthetic Biology Expert Agent 已经实现多个前端页面：

* Project Command Center
* DBTL Engineering Runtime / 思路工作台
* Knowledge & Evidence Layer（知识与证据）
* Trust & Provenance Center

近期前端测试发现 Knowledge & Evidence 页面存在几个疑似问题：

1. 本地 DDR 知识库搜索为空时，没有展示已有知识记录。
2. 文献详情中的“适用范围 / 情境匹配报告”为空。
3. “知识主张”为空。
4. 感觉 Knowledge & Evidence 页面与 Project Command Center、Design Workspace 之间没有形成数据联通。

注意：

不要直接假设这些都是 bug。

请首先以：

《260718-合成生物专家 Agent 平台设计思路》

作为设计标准，对当前代码进行架构审查。

目标不是补页面，而是确认当前系统是否真正实现：

Persistent, Traceable, Human-Governed DBTL Engineering System。

# 第二阶段：问题1——本地 DDR 知识库空搜索

## 当前现象

进入：

知识与证据 → 本地 DDR 知识库

搜索框为空：

没有任何记录。

请检查：

当前逻辑是否：

```
empty query
=
no request
```

或者：

```
empty query
=
return empty
```

## 设计目标

根据设计文档：

DDR 是 Agent 的决策记录语料库。

因此：

当用户没有输入关键词时：

应该展示当前系统已有的 DDR 记录。

不是展示论文列表。

而是展示：

```
DDR records
|
|-- design action
|-- target
|-- trigger
|-- evidence
|-- evidence grading
|-- rule
|-- provenance
```

请实现：

空搜索：

返回全部可用 DDR。

要求：

同时支持：

* 全量浏览
* 关键词搜索
* 项目过滤

# 第三阶段：问题2——适用范围 / 情境匹配报告

## 当前现象

点击某条 DDR 后：

“适用范围 / 情境匹配报告”为空。

请先判断：

当前系统是否已经存在 Context Matching 机制。

不要为了填页面制造假数据。

如果不存在：

请评估是否应该实现。

判断依据：

设计文档强调：

DDR 的价值不是记录某篇论文，而是抽取可以迁移到其他设计任务的决策逻辑。

因此需要回答：

某个历史设计决策：

是否适用于当前项目？

例如：

历史 DDR：

```
E.coli K12
解除反馈抑制
Trp pathway
```

当前项目：

```
E.coli K12
提高芳香族产物
```

应该能够判断：

* 宿主匹配
* 通路匹配
* 机制匹配
* 限制条件

如果实现：

要求：

输入：

```
DDR

+

Current Project Context
```

输出：

```
Applicability Report

match score

matching factors

limitations

confidence
```

如果当前架构没有足够信息：

明确记录：

需要哪些数据后才能启用。

# 第四阶段：问题3——知识主张 Knowledge Claim

## 当前现象

Knowledge Claim 页面为空。

请检查：

当前系统是否已经实现：

DDR aggregation。

设计文档中：

规则库来自多个 DDR 的蒸馏。

因此：

Knowledge Claim 不应该等于论文摘要。

应该表示：

多个 DDR 支持的可迁移知识。

例如：

多个 DDR：

* feedback resistance mutation
* transporter engineering
* pathway balancing

可以形成：

```
Claim:

解除反馈调控可以提升目标代谢流。

Evidence:

DDR001
DDR002
DDR003

Confidence:

High

Boundary:

需要实验验证
```

请判断：

当前是否已有：

* claim schema
* claim generation
* evidence aggregation

如果没有：

不要简单生成文本。

设计最小 Knowledge Claim 层。
