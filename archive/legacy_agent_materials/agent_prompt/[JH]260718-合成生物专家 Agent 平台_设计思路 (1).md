# 260718-合成生物专家 Agent 平台设计

## 一、定位

项目的目标是更深、更准地理解细胞:基因型如何一步步映射到蛋白组、代谢组,再到表型。建模 (虚拟细胞/扰动模型)和 Agent 都朝这个方向,是两条正交但同向的路径。

Agent track 具体做的是 E. coli K-12 底盘的理性改造设计。用户用自然语言提问,系统输出人能直接看懂的实验设计:改哪几个基因、用什么方式改、发酵条件如何、每条建议的依据和预测效果。代码在后端跑,对用户不可见。

只做理性设计,是刻意选定的范围,不是能力短板。理性设计是细胞因果逻辑中可机理解释的那一部分——每一步"为什么这么改"都能追溯到通路、酶、调控上的具体原因。适应性进化(ALE)产出的突变落在通量分支点、事前无法理性预测,不可机理解释,因此不在本项目范围内。选择只对标理性设计,和"理解细胞"这个目标是一致的。

范围界定:

|维度|初版做|
|---|---|
|产物/底物|单产物、单底物、单条通路|
|产物类型|天然产物(解除调控 + 通量集中)、非天然产物(通路预测 + 宿主改造)|
|设计类型|理性设计(可机理解释)|
|底盘|Ecoli K-12|

## 二、增益从哪里来

系统相对"直接问大模型"增量的候选来源列在下面,哪一项为主由消融实验判定,不预设结论:

|候选来源|说明|
|---|---|
|接地数字|理论得率、FBA 通量、基因必需性这类,裸模型仅能凭记忆;系统用工具算出真值|
|覆盖完备|对每个分支点逐一过一遍全部设计动作,不受单人经验偏好限制|
|精确调取先验|某个残基、某个 Km、某个启动子强度,通过决策记录/规则库检索精确取出|
|推理脚手架|把任务分解成专家的决策步骤,逐步接地|
|规则迁移|一类产物抽出的规则,用到另一类产物问题上|

一个待检验的判断:通用规则(解除反馈、敲竞争支、平衡表达)大多是教科书级,base model 可能已掌握;因此增益可能更集中在前三项(接地、完备、精确调取),而非后两项(通用推理、迁移)。这是消融实验要回答的问题,目前信息不足以下定论。

|工作|要回答的问题|产出|

## 四、工作 A:文献逆向工程

### 4.1 思路

一篇底盘改造论文可看成一条决策链:想产什么 → 观察到什么 → 提出什么假设 → 拿什么证据 → 做了什么改动 → 怎么验证 → 结果多少。逆向工程抽的是这条链,以及背后能迁移到其他产物的规则,而不是"他们改了哪几个基因"这张结果清单。清单只对这一篇有效,规则可用到下一个产物。

需要正视的一点:不是所有论文都有一条干净的决策链。相当一部分改造的真实理由是"上一篇这么做""Keio 库里现成有""筛库筛出来的",而不是机理推断。硬把这类论文凑成一条听起来合理的规则,会用事后编造的理由污染规则库。所以决策记录里显式记录理由的性质,不回避筛选和事后合理化的情况。

### 4.2 决策记录(DDR)字段

|字段|含义|
|---|---|
|设计动作|属于哪个模块(对齐第五节编号)|
|靶标|动了哪个基因/酶/通路/条件|
|触发|什么观察或推理触发了这一步|
|证据|具体证据,含出处和数值|
|证据分级|硬(实测:结构、动力学、已验证改造结果;或化学计量:理论得率、通量、必需性)/ 软(预测:OptKnock 生长偶联、de novo docking、ΔΔG,待实测确认)|
|理由性质|机理推断 / 文献类比 / 现成可得 / 筛选得来 / 事后合理化存疑|
|备选|考虑过又放弃的方案及原因|
|实现方式|KO / CRISPRi / 过表达 / 点突变 / 启动子 / 培养基 等|
|结果|量化结果(滴度/得率,前→后)|
|规则|从这一步抽象出的可泛化启发式(仅当理由性质为机理推断或可靠文献类比时才写)|

"证据分级"和"理由性质"两栏是这版新增。前者防止把不可靠的工具预测当硬证据;后者防止规则库被编造的理由污染。

### 4.3 抽取流程

1. 先手工深度策展 3–5 篇。

2. 每篇沿决策链通读,切成若干条 DDR。

3. 规则字段由两人独立写、再对齐,统一标注口径(解决"同一篇不同人抽出来不一样")。

4. 校准后作为示例,让 Agent 半自动抽取剩余论文,人工抽检。

5. DDR 入语料库;可靠规则去重后进规则库。

### 4.4 示例:色氨酸(Chen & Zeng 2018)

这篇决策链完整,理由多为机理推断,适合作模板。四条 DDR 串成一张决策图:

|步骤|设计动作|触发与证据|证据分级|结果|抽出的规则|
|---|---|---|---|---|---|
|1|解除末端反馈|Trp 对 committed 酶 TrpE 反馈抑制(已知)|硬|TrpE(S40F) 抗性突变|天然产物先查 committed 酶的末端反馈,用抗性突变解除|
|2|识别隐藏调控|加大上游拷贝数不增产、反而中间体 anthranilate 积累;晶体结构显示 anthranilate 与产物 IGP 互作|硬(结构)+ 软(docking)|体外确认非竞争抑制,IC50 0.70 mM|"加上游不增产、中间体积累"时,查该中间体对下游酶的前馈抑制|
|3|理性突变去抑制|结合位点紧邻催化位点|硬|S60A 抗性升约 3 倍但比活下降|去抑制常有比活代价,记录 trade-off 并准备替代路线|
|4|异源酶替换|A. niger 同工酶的 IGPS 被 anthranilate 前馈激活而非抑制|硬|Trp 19→29 g/L,得率 0.15→0.18(理论上限 0.227)|本源酶去抑制有代价时,跨物种筛反向调控的同工酶|

Agent 面对新的天然产物,应遍历同构的这张图,在每个节点查库、跑工具接地,而不是直接背出"改 TrpE 和 TrpC"。

### 4.5 规则库样例(跨论文蒸馏)

|规则|来源论文|证据分级|
|---|---|---|
|天然产物去调控:committed 酶查末端反馈,中间体查对下游酶的前馈;首选抗性突变或反向调控的异源同工酶|色氨酸|硬|
|通量集中:敲发酵副产物途径(ldh/adh/pfl/pta/frd),还原态产物再敲还原支(mdh)并解阻遏(arcA)|BDO、丁醇、脂肪酸|硬(得率结果)+ 软(OptKnock 预测)|
|可逆通路要驱动力:CoA 依赖链延伸通路需不可逆步/辅因子积累/产物移除,缺驱动力滴度约低一个数量级|丁醇|硬|
|表达非线性:整条通路一起过表达很少给最大通量,启动子×拷贝数存在内部最优,需多变量搜索并留意冒出的抑制性副产物|紫杉二烯|硬|
|有毒中间体用动态控制:静态启动子导致失衡,用代谢物响应传感器门控消耗模块|脂肪酸 DSRS|硬|

规则库把一类产物的规则用到另一类问题上(如丁醇的驱动力规则用到脂肪酸),是单个专家容易漏、系统能系统覆盖的地方。这一项的实际迁移效果需随语料扩大持续检验。

## 五、工作 B:模块划分

### 5.1 划分原则

模块按"专家做的一个设计动作"划分,不按组学层次(基因组/转录组/蛋白组/代谢组)划分。原因:最终输出是实验设计,组学分层与用户实际问的问题对不齐。组学作为横切证据来源存在——多个模块都可从组学取证据,后续也可作为用户上传数据的可选输入——但不单独成模块。

### 5.2 模块清单

|编号|模块|决策问题|主要工具/数据库|
|---|---|---|---|
|M0|意图解析与靶标框定|产物是否天然?de novo 还是生物转化?宿主/约束?|产物-通路-前体图|
|M1|通路解析|走哪条通路?最大理论得率?|EcoCyc/KEGG;RetroPath(非天然);COBRApy|
|M2|前体与还原力供给|前体够不够?需不需要驱动力?|COBRApy(pFBA);BRENDA|
|M3|解除调控|committed 酶有无反馈/前馈/转录阻遏?|EcoCyc/RegulonDB;PDB+docking|
|M4|限速酶识别与工程|哪个酶限速?理性突变还是异源替换?|BRENDA;UniProt/PDB;AlphaFold+FoldX|
|M5|竞争/旁路通量阻断|敲哪些基因把碳流集中且不致死?|OptKnock;COBRApy 必需性反查|
|M6|表达平衡|启动子×拷贝数×基因顺序怎么配?|RBS Calculator;iGEM parts|
|M7|动态调控|有毒中间体是否需要传感器门控?|RegulonDB;STRING|
|M8|副产物与毒性管理|会不会冒出抑制性副产物?|EcoCyc;DDR 语料|
|M9|发酵与过程|培养基/诱导剂/通气/pH/产物移除?|DDR 语料(从论文摘出)|
|M11|集成、筛选与一致性|组合是否自洽?优先级?能否筛掉不够好的方案?|一致性采样器;evaluator|

优先级:先做通路上的基因级改动(M3/M4),再做旁路抑制(M5),再落到发酵(M9),最后集成筛选(M11)。

初版先建 8 个即可跑通一个天然产物端到端:M0、M1、M2、M3、M4、M5、M9、M11。M6/M7/M8 第二期补。

### 5.3 四类资源映射

系统靠四类资源支撑:外部数据库、外部工具、自建数据库、自建工具。

|类别|具体项|用途|
|---|---|---|
|外部 DB|EcoCyc(已爬取)|K-12 通路/酶/调控/基因功能主干|
|外部 DB|KEGG|通路/反应/直系同源|
|外部 DB|iML1515(BiGG)|基因组尺度代谢模型,FBA/OptKnock 底座|
|外部 DB|BRENDA|酶动力学 Km/kcat/抑制剂|
|外部 DB|RegulonDB / iModulon|转录调控、转录模块|
|外部 DB|STRING|蛋白互作图先验|
|外部 DB|UniProt / PDB / AlphaFold DB|序列、结构域、结构|
|外部工具|COBRApy|FBA/FVA/pFBA/基因敲除模拟|
|外部工具|OptKnock / cameo / straindesign|生长偶联 KO 策略(软证据,需实测)|
|外部工具|RetroPath2 / novoStoic|非天然产物通路枚举|
|外部工具|eQuilibrator|反应热力学 ΔG|
|外部工具|AlphaFold/ESMFold + FoldX|结构预测 + 突变 ΔΔG(软证据)|
|外部工具|RBS Calculator|RBS 强度|
|自建 DB|DDR 语料|论文决策轨迹,检索式复用|
|自建 DB|规则库|可泛化启发式|
|自建 DB|模块注册表|模块 I/O 契约|
|自建 DB|产物-通路-前体图|常见产物的策展映射|
|自建工具|一致性采样器|跑 N 次、聚类干预、报收敛|
|自建工具|虚拟细胞/扰动模型(建模 track,后续)|由基因型预测蛋白组/代谢组/滴度,替换 FBA|

外部工具里 OptKnock、docking、FoldX 标为软证据:它们对化学计量/结构存在给强接地,对动力学、生长偶联、酶活性的预测在实验里经常不兑现。系统采用它们的输出时,在设计报告里标为"假设,需实测确认",不与实测证据同权。这也是建模 track 的虚拟细胞模型将来要补强的地方。

### 5.4 标准输入输出

所有模块用统一契约。输入:靶标规格、当前设计状态、相关通路子图。输出:提议的改动、每条改动的证据及分级、量化预测、置信度、需实测的点。

其中"证据"字段强制非空:任何一条改造建议必须挂到一条论文先例、一次工具预测、或一条数据库记录上,并标明证据分级,否则不进入设计方案。

## 六、工作 C:Workflow 编排

初期不追求大规模并行。把标准编排模式用好即可:

|模式|在系统里的用法|
|---|---|
|串行(prompt chaining)|主干相位 Phase0→Phase7,每相位消费上一相位的输出。适合可稳定分解的固定流程|
|routing|M0 按产物类型(天然/非天然)和问题类型(设计新株/诊断卡点/优化现有株)把任务导向不同后续。天然产物走去调控+通量集中,非天然走通路预测+宿主改造|
|并行 - sectioning|Phase2 的 M2/M3/M4/M5 对通路上不同分支点独立分析,并行跑,互不阻塞|
|并行 - voting|一致性采样:同一设计任务跑 N 次,对干预聚类,看哪些稳健收敛|
|orchestration|主 Agent 持有设计骨架和状态,把各模块作为 worker 委派,再综合。适合子任务内容事前不完全确定的情况|
|evaluator-optimizer|M11 集成相位是生成-评审回路:生成器提设计,评审器查自洽性(要敲的基因是否下游必需、证据是否齐备、软证据是否被当硬证据)并筛掉仅表面合理的方案,不合格打回重来|
|subagent|orchestration 里的 worker 即子 Agent,上下文与主 Agent 隔离,只装本模块需要的证据,处理完压成结构化结论回传。只在某模块需深读一篇论文/一个酶结构时用来隔离上下文,不做几百个并行|

相位流程:

```Plain Text
Phase0 框定(M0,routing)
  → Phase1 通路解析(M1)
  → Phase2 靶标分析(M2/M3/M4/M5 并行-sectioning)
  → Phase3 干预设计
  → Phase4 集成筛选(M11,evaluator-optimizer,汇聚屏障)
  → Phase5 发酵过程(M9)
  → Phase6 一致性采样(并行-voting)+ 验证方案
  → Phase7 输出设计报告
```

Phase3→Phase4 是汇聚屏障:必须拿到所有靶标分析结果才做全局自洽检查(例如旁路要敲的基因不能是限速酶下游需要的;对应 BDO 论文里丙酮酸脱氢酶必需、不能敲的反查)。

## 七、验证方式

评估不以"复现论文"为金标准。论文的设计只是可行空间里的一个点,还被当年的可得性和流行带偏;若论文在 base model 训练里,裸模型也会复述。高召回不等于理解,低召回不等于错。

真正要看的:Agent 是否真的理解一条理性设计路径——表现为它能生成有据的合理新颖设计,并能把不够好的候选筛掉,留下值得构建的少数。这一步落在 evaluator-optimizer 回路上,由湿实验最终验证。

指标分三层:

|层|指标|含义|
|---|---|---|
|过程|接地率|每条建议是否挂到证据、证据分级是否正确(直接反映是否跑赢参数记忆)|
|过程|覆盖完备|是否系统过完所有分支点 × 设计动作|
|能力|筛选能力|能否剔除弱证据、自相矛盾、仅表面合理的方案|
|能力|合理新颖|不在论文里、但有据的设计|
|能力|一致性|N 次采样的收敛度|
|结果|湿实验验证|Agent 留下的少数合理新颖设计,实际构建、测滴度/得率——唯一金标准|

复现率保留为 sanity check(能否至少复述论文里的关键理性改动),不作主指标。

说明:进化涌现的突变无法理性预测,不评;初期论文少,统计结论弱,这是 proof-of-concept 阶段,完整评估需更大的策展语料。不与定向进化/多轮诱变对比,因为那些基因型已偏离 K-12,无法对标。

## 八、落地路线

### 8.1 第一个端到端目标:色氨酸

理由:天然产物(核心场景)、有完整论文当参照、决策链丰富且多为机理推断(反馈+前馈+酶工程+异源替换)。

工具用 COBRApy + iML1515 + EcoCyc + BRENDA + docking,全部 CPU 可跑,不占 A100。

原型算成功的最低标准:

1. 输入"葡萄糖产色氨酸",系统自动查出 trp 通路 + 分支点,给出最大理论得率(≈0.227 g/g)。

2. M3 查出 TrpE 末端反馈,提议抗性突变;并在检索到色氨酸 DDR 后,主动提出核查 anthranilate 对 IGPS 的前馈抑制(裸模型基本给不出,是增益的直接证据)。

3. M5 用 OptKnock 给出竞争支敲除集 + 必需性反查,结果标为软证据。

4. M11 跑 20 次,报告哪些干预稳健收敛,并筛掉证据不足的方案。

5. 输出一张人能看懂的设计表,每条带证据出处和分级。

达到这 5 条,即有一个原型,可拿去给合成生物专家评审、并进入湿实验验证。
